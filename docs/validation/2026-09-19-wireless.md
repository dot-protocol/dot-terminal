# Wireless device and clipboard validation

Date: 2026-09-19. Local development build, macOS ARM64 and Motorola G67 Power 5G,
Android 16 ARM64. This is a bounded real-device check, not a security audit or a
claim of production mesh readiness.

- Enrolled Android Keystore certificate over authorized USB debugging; no private
  key was exported. Mac server certificate pinned in the app's private profile.
- Removed all adb reverse mappings. The old USB HTTP bridge was stopped.
- Connected to the Mac LAN IP over TLS 1.3, took control and issued a synthetic
  shell command from the phone; its exact output appeared in the phone VT view.
- Force-stopped/reopened the app; the exported public certificate and keeper PID
  were unchanged, and prior synthetic output remained visible after reconnect.
- Replaced the expected server certificate with an unrelated test certificate:
  Android refused connection with an identity mismatch. Restored the authentic
  profile and connected again. There was no plaintext fallback.
- Read a synthetic Mac clipboard into Android, changed the Mac clipboard, then
  sent Android's copy back. Exact marker equality proved both directions. The
  original Mac clipboard items/types were held only in memory and restored;
  Android Undo restored the previous phone clip. Private contents were not logged.
- Rust TCP/TLS integration rejects missing, unregistered and revoked client
  identities, an incorrect server trust root, and clipboard requests without
  their separate grants. Protocol tests reject unknown service fields/types and
  enforce clipboard limits in UTF-8 bytes.
- Local Rust format/Clippy checks and 22 Rust tests pass; four Python bridge tests
  pass. ARM64 JNI Clippy, APK build and Android lint pass.
- Final installed APK bytes match the locally built APK by SHA-256:
  `93877c80e24e869f9f435cb7512f840ed8773faf8afa0eee4b898e6c7ef9a88f`.

The Android Keystore key permits DIGEST_NONE because the TLS implementation hashes
handshake data before requesting the private-key signature. Omitting this caused
INCOMPATIBLE_DIGEST on the actual device; enabling the documented key usage fixed
it without disabling certificate validation. The development key alias advanced
from v1 to v2 and was explicitly re-enrolled during this unreleased work.
See [Android's key configuration documentation](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec.Builder#setDigests(java.lang.String...)).

Not established: hardware-backed key attestation; battery/throughput benchmarks;
cellular NAT traversal; discovery after IP changes; VPS/Windows/iOS interoperability;
concurrent multi-session UI; automatic background clipboard; file transfer; signed
wireless updates; recovery or coordinator outage behavior. Debug APK signing is
local development signing, not a supported release channel.
